## Findings (written after the run)

Compared with [m1-lossless-20261101-0344](m1-lossless-20261101-0344.md), the run before
this change (same machine, same bench, the screen model lossless in both):

| Test | before | now | faster |
|---|---|---|---|
| `seq 1 5000000` wall | 59.58 s | 25.25 s | 2.4× |
| `cat` 50 MB coloured log, wall | 45.96 s | 14.66 s | 3.1× |
| Key → echo, other window floods (median) | 1.7 ms | 1.9 ms | same |

1. **Where pyte spent the time** (cProfile, the parser alone on 2.3 MB of `seq` and 3 MB
   of the coloured log): `draw()` builds one namedtuple per character (`_replace`);
   the stream sends every control character and every byte of an escape sequence
   through a generator, one call each; `index()` moves the rows up in a Python loop on
   every line feed, and every new line built a fresh blank cell and a generic alias.
2. **What changed** (`src/py_screen/screen.py`): runs of one-cell characters are written
   a line slice at a time (one `dict.update`, cells cached per set of attributes); plain
   text, `\r \n \b \t`, and complete CSI sequences are dispatched from the parser's
   ground state with one regex each; `index()` moves the rows with one C-level update;
   new lines share one blank cell. Everything else still goes through pyte.
3. **Same result, cell for cell**: tests/test_parser.py feeds random streams to these
   paths and to pyte's own code, cut into random reads, and compares every cell, the
   cursor, modes, margins, title and dirty lines after each read (400 seeds in the
   suite; 3,000 run once by hand on the final code).
4. **Parser alone**: scrolling text 0.85 → 1.71 MB/s, coloured log 1.36 → 4.09 MB/s.
   End to end, floods are now **about 2× screen's time** (from 4–6×). What remains is
   Python's cost per line (about 4 µs: a draw call, CR, LF, the row shift); a native
   parser is the way past it.
5. **Three pyte bugs that dropped bytes**, found by the fuzz test: pyte raises out of
   `feed()` on a CSI with an extra parameter (`ESC [ 1 ; 2 B`), a `?` its handler doesn't
   take (`ESC [ ? 5 B`), an erase value it doesn't know (`ESC [ 3 K`), and VPA or a
   cursor report in origin mode without margins (an `assert`). The brain didn't catch
   it, so the rest of that read was lost: the same harm as the dropped bytes of v2.
   Now extra parameters are ignored (as terminals do), the rest are no-ops, and nothing
   after them is lost.
