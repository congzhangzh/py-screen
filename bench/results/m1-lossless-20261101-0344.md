- Machine: local desk, 8 CPUs, Python 3.14.8
- screen: Screen version 5.0.2 (build on 2026-11-01 03:06:17), minimal screenrc (status line, 10000 scrollback)

## Findings (written after the run)

1. **The screen model is now lossless** (spec v3 §8.1): every byte is parsed; the brain
   acks the keeper only after parsing, so a flood is held back by the keeper's credit
   instead of dropped. Claude Code and other diff renderers stay exact, hidden or shown
   (tests/test_redraw.py; both tests fail on 9fb99f5).
2. **Floods are 4–6× slower than in screen**: `seq` 59.6 s (0.65 MB/s), `cat` 46.0 s
   (1.1 MB/s). That is pyte's own speed (measured alone: ~0.75 MB/s scrolling text,
   ~2.6 MB/s escape-heavy), so the multiplexer adds little; a faster parser is the only
   way to faster floods. The earlier 3–4× *faster* rows came from dropping bytes.
3. **Typing during a flood stays as quick as screen's**: 1.7 ms median, 4.4 ms p95, from
   2 ms parse steps and "keys first" (100 ms after a key, only shown windows are parsed).
   Without "keys first" the median was 32 ms; with 8 ms steps, 166 ms.
4. Server CPU during a flood equals the flood's duration (one core, parsing).
